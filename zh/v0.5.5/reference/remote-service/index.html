远程服务部署与缓存¶

用户连接步骤见使用远程文件。本页供部署和维护服务时查阅。

Linux 启动包由维护者运行 bash scripts/package-server.sh 或 GitHub 的 Package C-Studio server 工作流构建，支持 x86_64 / ARM64；构建不会自动发布版本。

构建服务¶

在 C-Studio 源码目录运行：

cargo build --release \
  --manifest-path crates/cstudio-server/Cargo.toml \
  --features portable-hdf5

portable-hdf5 会在构建时编译 HDF5 和 zlib，因此服务端机器不需要另外安装 HDF5 运行库。生成的程序位于 crates/cstudio-server/target/release/。

在本机启动¶

crates/cstudio-server/target/release/cstudio-server \
  --dataset example=/absolute/path/to/input.mcool

默认只监听 127.0.0.1:8787。在 C-Studio 中选择 Add Data → Remote project or file…，输入：

http://127.0.0.1:8787/v1/datasets/example

可以重复使用 --dataset ID=PATH 发布多个白名单文件。客户端不能传入任意服务器 文件路径。

提供给另一台机器¶

创建一个只含高强度 bearer token 的文本文件，然后在私有网络接口启动服务：

crates/cstudio-server/target/release/cstudio-server \
  --bind 0.0.0.0:8787 \
  --token-file /absolute/path/to/cstudio-token.txt \
  --dataset example=/absolute/path/to/input.mcool

在 C-Studio 连接窗口输入同一 token。token 只保存在当前应用的内存中，不会写入项目文件。

如果流量会离开可信私有网络，应在服务前配置 HTTPS 反向代理，并使用 https:// 数据集地址。明文 HTTP 中的 bearer token 可能被截获。除非显式传入 --allow-unauthenticated-remote，服务会拒绝“非本机监听且无 token”的配置。

API 边界¶

API v1 提供：

方法 路径 用途
GET /v1/health 存活状态与 API 版本
GET /v1/datasets 已注册数据集
GET /v1/datasets/{id}/metadata 格式、大小、分辨率和染色体/来源
GET /v1/datasets/{id}/assembly 配套 AGP
POST /v1/datasets/{id}/layouts 注册布局版本
POST /v1/datasets/{id}/render 服务端生成的热图 PNG
GET /v1/datasets/{id}/cache 缓存与预热状态
POST /v1/datasets/{id}/overview 有大小上限的导航概览
POST /v1/datasets/{id}/tiles 稀疏二进制 CST1 接触矩阵 tiles

客户端注册 AGP 布局后按版本引用，因此服务端投影与桌面工作区中的顺序、方向和来源 区间一致；旧服务不支持注册时回退为发送完整布局。数据集始终只读，没有修改源文件的 API。

远程端要求¶

  • 服务进程需要读取每个已注册 .cool/.mcool 文件及穿过其父目录的权限。
  • 服务运行期间保持数据文件不变；更新文件时应重启服务，而不是原位覆盖。
  • SSH 模式通过隧道访问本机监听端口；直接连接时确保客户端可访问服务地址。
  • 如果服务超出单台可信工作站使用范围，用反向代理提供 TLS、访问日志、限流和组织认证。

当前实现会复用单个 C-Studio 服务进程内已有的 reader cache，但尚未提供分布式 tile 缓存、可恢复的离线下载，或 PAF/GFA/coverage 的服务端计算。

服务端渲染模式¶

新版客户端连接支持 png-v1 的服务时，自动使用服务端渲染。Linux 服务读取矩阵、 按当前 AGP 布局投影、聚合并着色，然后通过 POST /v1/datasets/{id}/render 返回 PNG。 主视图和导航概览都使用该模式。客户端保留选区、坐标轴及编辑操作，仅绘制返回图像， 不为主视图下载矩阵 tiles，也不建立矩阵 GPU atlas。

更新客户端与服务端后，沿用上面的构建、启动和连接步骤即可。状态栏会显示 server rendering / Server rendered contact map。旧服务未声明该能力时仍使用原有 客户端渲染路径，连接提示会说明升级服务可以降低内存。

  • 单张图最多 1,048,576 像素，单边最多 2048；分辨率随视野按屏幕尺寸聚合，状态栏报告 实际显示 bin 大小。选中的矩阵分辨率仍是读取层级，不保证一条 bin 对应一个屏幕像素。
  • 服务每进程最多同时运行两个 PNG 渲染任务；繁忙时返回 429，客户端退避重试。 切换视野会中止旧请求，过期结果不能覆盖新视图；服务器在感知请求取消后协作停止读取。
  • 图像携带原始视野坐标，平移时仍按该坐标定位；布局修改后重新请求投影图像。 颜色、归一化和分辨率变更同样触发重新渲染。
  • 自动色阶按数据集、所选分辨率和对数设置复用，保持归一化切换时的阈值一致。
  • AGP 编辑仍在桌面端进行；PAF、GFA、coverage，以及主动触发的数值证据查询仍可能 使用本地内存。本模式不是完整网页客户端，也不是所有计算的远程化。

图像与聚合缓冲区有尺寸上限，但这些上限不是整个服务进程的 RSS 上限；HDF5 reader、 归一化权重、布局和并发读取也会占用内存。应使用用户的真实数据测量服务端和客户端 峰值内存与操作延迟后再确定部署规格。

自动加载服务器上的 AGP¶

将 AGP 放在已开放的 .cool/.mcool 同一目录。服务启动时优先读取同名 AGP（例如 sample.mcool 对应 sample.agp）；没有同名文件时，仅在目录 中只有一个 .agp 时自动选取。多个候选不会被随意选择。仅开放普通 AGP 文件，不跟随符号链接；文件上限 32 MiB。添加或修改 AGP 后重启服务。

空组装会话连接远程数据集时会自动获取配套 AGP，无需手动下载或选择本地文件。 已有组装或编辑内容会保留。GET /v1/datasets/{id}/assembly 与矩阵接口使用 相同的认证设置；未启用 token 时无需认证。返回的布局用于本地交互，矩阵读取和热图渲染 仍在服务器执行。 保存编辑结果仍使用本地导出，不会覆盖服务器原文件。

远程读取优化¶

远程主图使用与本地主图相同的 LOD 决策函数，显式发送读取和显示分辨率。 服务器不再根据图片大小自行更改此计划。预加载余量不会改变 bin 大小； 图像容量不足时先缩小余量。自动色阶仅统计与当前视野相交的正值非对角线 bin（包含镜像位置）， 按坐标散列取样，不受稀疏或稠密存储格式影响。有效 bin 不超过 10,000 时全部使用， 更多时约取十分之一。两条路径均等待可见 tile 完整后计算 P99。 色阶按分辨率缓存，最多保留 128 项。同一分辨率下拖拽保持 Max 稳定，切换分辨率 恢复该级别的估计值。点击 Auto 才按当前视野重新估计当前级别，即使 Auto 已启用 也会重新计算。手动色阶保持不变。 离散配色阈值、透明度和对数映射也使用同一约定。

服务进程缓存已投影的视野数据，预算 64 MiB、最多 256 项，按最近使用淘汰； 配色和色阶变化复用数据，但重新编码 PNG。缓存键包括数据文件路径、大小、 修改时间、AGP 布局、视野、读取及显示分辨率、归一化模式。此预算不包含 正在处理的请求和被请求持有的缓存引用，不是进程总内存上限。 响应头 x-cstudio-source-resolution 和 x-cstudio-cache 分别报告实际读取 层级和缓存命中情况。该服务端缓存不参与本地读取。为避免响应批次顺序改变颜色，两端首次自动色阶均等待可见 tile 完整。

普通远程主图使用固定 PNG 瓦片补充拖动中的新区域，并在停下后切换到精确视口图像。 布局、缩放或样式变化会使旧瓦片失效；详细行为见下文“拖动期间的图像瓦片”。

Overview 两端固定使用同一 320-bin 计划，不再由本地主图的完成时序替换其 分辨率；其 0.9 透明度、tile 采样与主图的 0.88 透明度分别保持一致。 新客户端会校验服务端显示契约和实际显示分辨率，旧服务不满足时提示升级， 而不是静默使用不同的规则。

完整 tile 的投影缓存按读取范围建立键，不包含 PNG 的精确裁切坐标。同一批 tile 内的平移可复用计数，仍按新视野重新绘图；布局、分辨率、归一化或文件 变化会使相关缓存失效。首次读取和跨入未缓存 tile 仍需要服务器计算。

布局版本与独立瓦片复用¶

客户端通过 POST /v1/datasets/{id}/layouts 上传布局，取得 layoutId 后， 主图、总览和拖动预取的 /render 请求仅携带版本引用。同内容的布局注册共享； 编辑后注册新版本。服务端注册表最多 32 个版本、32 MiB；重启或淘汰后返回 410， 客户端重新注册一次并重试。旧服务器不支持注册端点时，仍发送完整布局。

普通投影数据按独立瓦片缓存，跨瓦片平移只为缺失瓦片读取和投影；空瓦片也缓存。 缓存作用域包含布局版本、文件状态、读取/显示分辨率、归一化和 tile 大小。 64 MiB 是缓存预算，不是进程 RSS。自适应细化保留完整邻域缓存，避免改变其语义。 拖动中预取与松手复用仍然有效；首次数据读取仍需要时间。

自动预热与磁盘缓存¶

布局注册后，服务端低优先级预热 Overview、最粗存储层的数个显示层级，以及 预算允许的相邻粗存储层。全局预热最多排队 128 个瓦片；不会扫描全部细分辨率。 前台成功渲染后，后台补算当前瓦片周围一圈，最多 16 个邻域瓦片；最新邻域优先。 后台仅一个任务，前台请求到来时协作式取消；已有客户端拖动预取保持不变。 自适应细化不做独立邻域预热，以保持完整邻域的显示语义。

计数瓦片默认持久化到 $XDG_CACHE_HOME/cstudio-server/port-<端口>/counts-v1， 未设置 XDG 时使用 ~/.cache/cstudio-server/port-<端口>/counts-v1，默认预算 4 GiB。 环境变量 CSTUDIO_DISK_CACHE_DIR 可指定专用目录（服务在其下创建 counts-v1）； CSTUDIO_DISK_CACHE_MB 调整 MiB 预算，设为 0 关闭磁盘缓存；CSTUDIO_PREWARM=0 关闭后台预热。修改配置后重启服务；不同服务实例应使用不同的专用缓存目录。

缓存按布局内容、数据文件状态、读取/显示分辨率、归一化和瓦片尺寸隔离，重启后 同内容布局可复用，布局编辑使用新缓存。缓存带 SHA-256 校验；丢失或损坏时按未命中 重新计算。缓存文件写入失败不会阻止正常渲染。预算只限制缓存文件，不代表进程 RSS。 GET /v1/datasets/{id}/cache（仅在配置 token 时需认证）返回进程级磁盘命中和后台队列状态。 首次注册前尚无布局可预热；新布局和未覆盖的细层级仍可能需要等待。

拖动期间的图像瓦片¶

远程热图会在拖动时移动已有图像，并按固定基因组坐标预取附近的 PNG 瓦片。瓦片解码完成后直接更新画布，无需等鼠标松开；快速反向拖动会复用仍在缓存中的瓦片。请求按可见区域优先，最多同时加载两块，客户端解码图像缓存预算为 32 MiB。预取距离参考拖动方向、速度及近期加载延迟，并设有队列上限。

瓦片使用主视图同一套分辨率、归一化、配色及固定色阶。布局、样式或缩放条件改变时废弃旧瓦片。停止移动后仍保留精确视口渲染，校准最终像素边界；依赖完整邻域的自适应细化继续使用完整图像路径。首次进入未缓存区域或网络延迟很高时，新增细节仍可能稍后到达。

服务端缓存已编码的成品 PNG，命中后跳过投影、绘图和 PNG 编码。成品图内存缓存预算为 32 MiB，磁盘与数值瓦片共享 CSTUDIO_DISK_CACHE_MB 预算，重启后可复用。缓存按文件身份、布局内容及完整渲染参数区分；x-cstudio-image-cache: hit 表示成品图命中，/cache 的 images 字段报告进程内成品图缓存。预算不代表进程总 RSS。

升级服务端即可获得成品缓存；拖动中补图还需使用新版桌面客户端。先保存当前编辑，再退出并重新打开更新后的应用。
